
# Adaptive Temporal Detection of Denial-of-Wallet (DoW) Attacks in Serverless Cloud Environments

## Project Overview

Denial-of-Wallet (DoW) attacks are a security threat in serverless cloud environments where malicious or excessive function invocations can lead to unexpected resource consumption and increased cloud execution costs.

This project presents an adaptive, temporal deep learning-based approach to detect DoW attack patterns by analyzing serverless workload behavior over time.

The system combines temporal feature engineering, Kafka-based workload streaming, sequence-based deep learning inference, drift monitoring, and an interactive Streamlit dashboard.

## Objectives

- Detect potential DoW attack patterns in serverless workloads.
- Extract temporal features from function invocation events.
- Construct sequential input data for deep learning models.
- Evaluate LSTM, GRU, and TCN architectures.
- Monitor feature distribution changes using drift detection.
- Compare base and adaptive model performance.
- Demonstrate streaming inference using Apache Kafka.
- Visualize predictions and monitoring results through Streamlit.

The selected adaptive model was evaluated on the held-out test sequences.

|---|---:|

## Drift Monitoring

The project includes feature-level drift monitoring to identify changes in workload feature distributions.

- Statistical comparison of incoming feature distributions against a reference dataset.
- Monitoring of 18 selected input features.
- Synthetic drift validation using controlled feature shifts.
- Base and adaptive model performance comparison.

Synthetic drift validation demonstrated detection of the deliberately introduced feature distribution shifts.

## Streaming Demonstration

The streaming pipeline uses Apache Kafka to replay historical workload events in chronological order.

The demonstration processed:

- 10,000 workload events.
- 8,938 model predictions.
- 1,617 predicted DoW alerts.

These are simulated streaming results generated by replaying historical data, not measurements from a live serverless cloud deployment. Predicted alerts should not be interpreted as independently confirmed attacks.

### Run the Dashboard

First extract the ZIP archives into the project root.

Install the dependencies:

```bash
pip install -r requirements.txt
```

Start the dashboard:

```bash
python -m streamlit run src/dashboard.py
```

The dashboard requires the relevant model artifacts and result CSV files to be extracted into their expected project directories.

## Dataset

The project uses historical serverless workload data.

The raw dataset and large intermediate files are not included in this repository because of their size. Refer to the data preparation notebook for dataset provenance, preprocessing steps, and sequence construction.

The saved model artifacts and processed results are supplied separately in the repository ZIP archives.

## Limitations

- Streaming is demonstrated through historical workload replay rather than live cloud telemetry.
- Synthetic drift experiments validate detection of controlled distribution shifts, not all real-world drift scenarios.
- The drift reference is a sample of the training data.
- The offline test split is FunctionId-disjoint and is not a globally chronological split.
- Model performance on the held-out dataset does not guarantee equivalent performance in production.
- Predicted DoW alerts require further investigation before being treated as confirmed attacks.
